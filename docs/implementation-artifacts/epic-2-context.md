# Epic 2 Context: Studenter kan melde et problem

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

En besøkende oppretter konto og logger inn med e-post og passord, og en innlogget bruker registrerer en rapport med beskrivelse, lokasjon, kategori og valgfritt bilde. KI-en foreslår kategori og en kort oppsummering før innsending, og rapporten vises etterpå på detaljsiden med status **Ny** og «1 har sett dette». Epicen lar studentene selv melde problemer (UJ-1) og avgjør valget av KI-leverandør med et fast testsett. Alt skal virke uten nøkler: KI-en går i mock-modus, og sensor kan registrere rapporter lokalt.

## Stories

- Story 2.1: Konto og innlogging
- Story 2.2: Registrere en rapport
- Story 2.3: KI-forslag for kategori og oppsummering
- Story 2.4: Legge ved et bilde
- Story 2.5: Velge KI-leverandør med SM-5-testen

## Requirements & Constraints

- **Konto:** Registrering gir innlogging med en gang, uten e-postbekreftelse. Nye kontoer får rollen `user`, ingen navn lagres, og e-postadressen vises bare for brukeren selv. Besøkende kan bare lese; den som prøver å registrere, sendes til innlogging og så tilbake.
- **Rapport:** Beskrivelse (maks 1000 tegn), lokasjon (maks 200) og kategori (en av fem) er påkrevd, og tekst med bare mellomrom er tom. Grensene gjelder trimmet tekst og telles likt i skjemaet, i Server Action og i databasen, også med emoji og æøå: nøyaktig grensen godtas, ett tegn mer avvises alle tre steder. Rapport uten bilde og oppsummering lagres.
- **KI-forslag:** Kategorien er alltid en av de fem kodeverdiene, ellers «ingen forslag». Oppsummeringen er ren tekst på maks 300 tegn, også når brukeren skriver den selv. Timeout (5 s), feil eller ugyldig svar stopper aldri innsendingen. Uten nøkkel går KI-en i mock-modus.
- **Bilde:** Valgfritt, JPEG, PNG eller WebP, maks 5 × 1024 × 1024 byte, sjekket i skjemaet, i Server Action og i bucketen. Tom fil og svært store dimensjoner avvises uten at serveren går tom for minne. Filendelsen kommer fra bildetypen i fila, ikke fra filnavnet.
- **Personvern:** Serveren fjerner all EXIF (GPS, enhet, tidspunkt) før lagring, og bildet står riktig vei (test med oppdiktede GPS-koordinater). Rapporttekst og e-post logges aldri, heller ikke ved KI-feil. I mock-modus forlater ingen tekst maskinen.
- **KI-leverandør:** 20 oppdiktede norske beskrivelser, fire per kategori, med fasit. Vinneren treffer minst 16 av 20, gir gyldig JSON hver gang, svarer under 5 s og har ikke dansk eller nynorsk i oppsummeringene. Kandidater: Cloudflare, Groq og Mistral; avklar først betalingskort og inferenssted hos Cloudflare og gratisgrensene hos Groq og Mistral. Gemini gratis er utelukket, og med Mistral slås trening på dataene av. Bare testsettet sendes ut. Består ingen, forblir mock standard.
- **Ferdig (hver story):** Som i Epic 1: issue, egen branch, PR med `Closes #N`, Playwright, pgTAP og Vitest grønne, axe uten `serious`/`critical`, kjerneflyttesten utvidet bare med tastatur og uten `skip`/`fixme`, ingen horisontal scrolling på 360 og 320 px, rettigheter testet i databasen, testsammendrag og gjennomgangsfunn i PR-en. Regelendringer føres i planleggingsdokumentet (begge kopier) og `docs/beslutninger/` i samme PR. Siste story følger README på en ny klone.

## Technical Decisions

- **Innlogging:** Hver side og Server Action som krever innlogging, kaller `requireUser(returnTo)` først, som sender besøkende til `/auth/login?next=<sti>`. Rollen kommer fra brukerens rad i `profiles`, aldri fra JWT eller metadata. `next` går alltid gjennom `safeNextPath` og godtas bare når `new URL(next, origin).origin === origin`, ellers `/`; Vitest dekker `//x`, `/\x`, `https://x` og `javascript:alert(1)`. Nettleserklienten brukes bare i auth-skjemaene, aldri til data, og `proxy.ts` sender aldri besøkende til innlogging.
- **Profiler:** Bare triggeren `handle_new_user` (eneste `security definer`, `role = 'user'` hardkodet) oppretter rader. Ingen Server Action oppretter eller endrer `profiles`.
- **Skriverettigheter:** `authenticated` får INSERT på `reports` som kolonnegrant for `description, location, category, summary, image_path`, med `WITH CHECK (author_id = auth.uid())`. `author_id`, `status`, `hidden`, `created_at` og `status_changed_at` kommer fra `DEFAULT` og kan ikke settes av brukeren, og `anon` kan ikke sette inn. Lengdene ligger i `CHECK` med `char_length` og i `lib/limits.ts` med `[...s].length`, så pgTAP og Vitest kan vise at de teller likt.
- **Server Actions:** Svarer `{ ok: true, data }` eller `{ ok: false, error: { code, message } }` med lukkede koder (`unauthenticated`, `validation_failed`, `upload_failed`, `ai_unavailable`, `unknown` med flere) oversatt i `lib/errors.ts`; tekst fra Supabase vises aldri. Tekst trimmes, og tom tekst lagres som `NULL` (også tomt KI-svar). Sjekk både `error` og antall rader, og kall `revalidatePath` for lista og detaljsiden.
- **`lib/ai`:** `suggest(description)` gir `{ category, summary }` eller `null`. Adapterne mock og OpenAI-kompatibel velges med `AI_PROVIDER=mock|openai`; URL, modell og nøkkel leses i `lib/env.ts` og står i `.env.example` uten verdier. Be om JSON (`response_format`) der det støttes, og tål JSON i kodeblokk. Kategorien valideres eksakt mot `Constants`, så feil store og små bokstaver og norske navn avvises. Høyst 2000 tegn sendes, og hver bruker har høyst ett kall i gang (lås i minnet). Kalles bare fra en Server Action for innloggede; en besøkende får `unauthenticated`. Mock svarer etter nøkkelord («gatelys» → `lighting`) og har et testord som gir `null`; testkommandoen setter `AI_PROVIDER=mock`.
- **SM-5-skriptet:** `evals/sm5/` bruker samme `lib/ai`, sier fra ved mock og viser treff av 20, JSON-gyldighet, svartid og oppsummeringene. Valget føres i `docs/beslutninger/`, og Deferred-raden i arkitekturen, det åpne spørsmålet i PRD-en og `.env.example` oppdateres.
- **Bildeopplasting:** Server Action validerer, fjerner EXIF og laster opp med brukerens sesjon til den private bucketen `report-images`, sti `<author_id>/<uuid>.<ext>`, ny uuid og uten `upsert`. Bildet lastes opp først; feiler rapporten etterpå, blir fila liggende ulesbar (ingen DELETE-policy, opprydding utsatt). `serverActions.bodySizeLimit` må romme 5 MB. Storage avviser fremmed mappe (`403`/`42501`) og feil type (`415`). EXIF-regelen føres i arkitekturens bildebeslutning og biblioteket i Stack-tabellen.
- **Avhengigheter og miljø:** Eksakte versjoner, aldri `latest`, og ny npm-pakke krever oppdatert Stack-tabell. Miljøvariabler leses bare i `lib/env.ts`. `supabase/config.toml` endres bare i en egen commit.

## UX & Interaction Patterns

- **Meny:** Knappen ☰ (`aria-label="Meny"`, 44 × 44 px) til høyre i topplinja, lik for alle. Besøkende: «Logg inn» med siden de står på som `next`. Innlogget: egen e-post, merkelappen «Moderator» for moderatoren og «Logg ut», som viser lista som for en besøkende. Enter eller mellomrom åpner, piltastene flytter, Escape lukker og gir fokus tilbake til knappen.
- **Innlogging og registrering:** Feltene «E-post» og «Passord»; registreringen har «Minst 6 tegn.» og ikke noe gjenta-felt. Knappene viser «Logger inn …» og «Registrerer …». Lenkene «Har du ikke konto? Registrer konto» og «Har du allerede konto? Logg inn» beholder `next`. Ingen «Glemt passord» eller sletting av konto i v1.
- **Auth-feil:** Feltfeil før sending («Skriv inn e-postadressen din.», «Skriv inn passordet ditt.», «Skriv inn en gyldig e-postadresse.», «Passordet må ha minst 6 tegn.», og «Det finnes allerede en konto med denne e-postadressen.») står under feltet med `aria-invalid`. Andre feil står over knappen med `role="alert"`: «Feil e-post eller passord.», «For mange forsøk. Vent litt og prøv igjen.» eller «Noe gikk galt. Prøv igjen.». Fokus til første feil, og det brukeren skrev, beholdes. Feiltekst har vanlig farge og et ikon i `destructive` (kontrast).
- **Inngang til skjemaet:** Under 640 px en flytende «+»-knapp, 56 px, nede til høyre, `aria-label="Registrer problem"`, eneste egne skygge. Fra 640 px primærknappen «Registrer problem» i topplinja. Tomtilstanden i lista lenker samme sted.
- **Skjemaet:** Fokus i beskrivelsen ved åpning, synlig `label` og 16 px tekst. Beskrivelsen har telleren «N/1000» (leses ikke opp per tegn) og «Ikke skriv navn eller andre personopplysninger. Teksten sendes til en KI-tjeneste for å foreslå kategori.» Kategoriene fra `lib/labels.ts`. Lokasjonen har plassholderen «F.eks. gangveien ved bygg A».
- **«Send inn»:** Deaktivert til de tre feltene er fylt, og mens KI-en jobber hvis brukeren ikke har valgt kategori selv. «Sender …» underveis, deretter detaljsiden med toasten «Rapporten er sendt inn». Valideringsfeil står under feltet (`aria-describedby`) med fokus til første feil. Feiler innsendingen: destructive-toasten «Kunne ikke sende inn. Prøv igjen.», og alt, også bildet, beholdes.
- **KI-tilstander:** Forslaget hentes når brukeren forlater beskrivelsen med minst 10 endrede tegn siden forrige forslag, aldri mens hen skriver. Imens «Finner kategori …» med spinner, og kategorivalget kan brukes. Et forslag velger kategorien med pillen «Foreslått av KI» (`ai-tag`) og leses opp som «Kategori foreslått: Belysning» (`aria-live="polite"`). Pillen forsvinner ved eget valg, og KI-en overskriver aldri et eget valg. Oppsummeringen vises med «Endre». Uten forslag: «Vi fikk ikke et forslag. Velg kategori selv.», og kategorien står tom og påkrevd. Mock ser ut som et vanlig forslag.
- **Bilde:** «Legg til bilde» åpner kamera eller bildebibliotek på mobil, med «Unngå ansikter og bilskilt på bildet. JPEG, PNG eller WebP, maks 5 MB.» under. Forhåndsvisning med 12 px hjørner kan fjernes. Feil fil avvises med en gang ved feltet.
- **Tester:** axe skanner skjemaet tomt, med valideringsfeil, med KI-forslag og med valgt bilde. Kjerneflyttesten logger inn, bruker mock-forslaget, legger ved et bilde (filvalget er unntatt tastaturkravet) og registrerer bare med tastatur på 360 px.
- Tone: du-form, kort og saklig, ingen utropstegn eller emoji.

## Cross-Story Dependencies

- **Fra Epic 1 (ferdig):** Lista, detaljsiden, visningen `reports_with_counts`, signert bildelenke i `lib/supabase/images.ts` og bildeikonet i lista finnes, så Story 2.4 bare laster opp. `safeNextPath` i `lib/safe-next.ts` sjekker `next`.
- **Fra Story 2.1 (ferdig):** `getViewer()` (`{ user, isModerator }`) og `requireUser(returnTo)` i `lib/supabase/auth.ts`, menyen ☰, auth-sidene og `lib/auth-errors.ts` (faste norske meldinger for Supabase-feil) finnes nå.
- **Fra Story 2.2 (ferdig):** Migreringen `20261110120000_skriving_reports.sql` gir `authenticated` INSERT på de fem kolonnene (også `summary` og `image_path`). `createReport` i `app/rapporter/ny/actions.ts` satte i 2.2 bare inn `description`, `location` og `category`, og setter fra 2.3 også inn den valgfrie `summary`. `lib/report-input.ts` (`parseReportInput`, Zod) validerer for både skjemaet og Server Action, og `lib/errors.ts` har hele feilvokabularet (`ActionResult`, `actionError`, `toActionError`). `components/report-form.tsx` (klient) har skjemaet, live validering, `aria-required`, destructive toast og `router.replace` til detaljsiden; kategorivalget er shadcn `Select`, og `<Toaster />` (Sonner) står i `app/layout.tsx`. Påminnelsen under beskrivelsen har nå hele teksten, også setningen om KI-tjenesten (lagt til i 2.3). `e2e/a11y.ts` venter på at toasts er ferdig animert. «←» etter innsending når skjemaet var første side i fanen er utsatt til Story 3.3.
- **Fra Story 2.3 (ferdig):** `lib/ai` (`suggest` i `index.ts`, adapterne `mock.ts` og `openai.ts`, `validate.ts`) er eneste inngang til KI-forslag, og Server Action `suggestReport` i `app/rapporter/ny/actions.ts` kaller den for innloggede. `lib/suggest-trigger.ts` (`charsChanged`, terskel 10 tegn) og `components/ai-tag.tsx` hører til skjemaet, som henter forslag ved blur på beskrivelsen. Mock-adapteren har testordet `ingenforslag`, som gir ingen forslag, og e2e-tester som velger kategori selv, bruker det. Story 2.5 bruker `suggest` fra SM-5-skriptet.
- **Rekkefølge:** 2.2 gir skjemaet, Server Action og INSERT-reglene som 2.3 og 2.4 bygger på. 2.3 gir `lib/ai`, som 2.5 bruker.
- **Hvis tiden blir knapp:** Forenkle 2.5 først (én leverandør, eller behold mock). Deretter kan «Registrer problem» i topplinja droppes til fordel for den flytende knappen på alle bredder, men da må `EXPERIENCE.md` (begge kopier) og beslutningsloggen oppdateres.
- **Utsatt arbeid:** «←» på detaljsiden bør gå til lista når forrige side er skjemaet eller innloggingen (Story 2.2). En norsk `app/not-found.tsx` for ukjente URL-er mangler.
- **Senere epics:** Epic 3 bruker `requireUser` for bekreftknappen og `authored_by_me` for «Mine rapporter». Moderatorrollen fra `getViewer` brukes i Epic 4.
