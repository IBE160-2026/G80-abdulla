## 2026-11-22 kl. 14:25 — Ali Yousef Abdulla

### Oppgave
Ta ned Vercel-siden `https://g80-abdulla.vercel.app`, som PRD §6 sier ikke skal finnes (v1 settes ikke i drift) og som README ikke lenger viser.

### Plan
- Jeg hadde ikke Vercel CLI eller innlogging. Prosjekteieren valgte å logge inn selv (`! npx vercel login`), så sletter jeg prosjektet.
- Liste prosjektene, få prosjekteierens bekreftelse på navnet etter at konsekvensene var vist, slette og kontrollere at adressen ikke svarer lenger.

### Resultat
- Kontoen hadde ett prosjekt, `g80-abdulla`, sist oppdatert samme dag (trolig bygget ved push via Git-koblingen), Node 26.x.
- `vercel project rm g80-abdulla --yes` ble avvist: Vercel godtar ikke `--yes` som godkjenning for sletting. Etter prosjekteierens eksplisitte «ja slett g80-abdulla» kjørte jeg kommandoen Vercel selv foreslo, `vercel project rm g80-abdulla --confirm-name g80-abdulla`. Svar: «Deleted g80-abdulla».
- Etterpå: `vercel project ls` viser ingen prosjekter, og adressen svarer HTTP 404.
- `issues.md`: punktet om at siden fortsatt svarte er lukket. Beslutningsloggen trengte ingen ny linje, siden linjen om Vercel (2026-11-22) allerede sier at v1 bare kjører lokalt.
- Vercel CLI ble lastet ned midlertidig med `npx`, ikke lagt inn i prosjektet. `package.json` og repoet er uendret.

### Åpne punkter
- Vercel CLI står fortsatt innlogget på maskinen (`npx vercel logout` fjerner innloggingen).
- Vercel viste en anbefaling om tofaktorinnlogging (2FA) for kontoen. Det er prosjekteierens valg.
- Resten av punktene fra retroen: README på en ren maskin og CI på PR-er (`epic-2-retro-item-9`).
